# Localization (Phase 04)

Phase 04's specification takes precedence over the earlier draft of this document. UI fallback, required business translations, and missing pages have different policies.

## Configuration and routing

`src/config/site.ts` owns the `locales` tuple (`ru`, `kk`), derived `Locale`, default locale, native language labels, and `parseLocale`. Unsupported locale values throw. `astro.config.mjs` configures Astro 7.4.8 native i18n with both locales prefixed, static output, and `trailingSlash: 'always'`.

The four business routes are `/ru/`, `/kk/`, `/ru/services/`, and `/kk/services/`. Their implementation is shared in `src/pages/[locale]/[...slug].astro`; explicit Astro composition selects the Home or Services layout. There is no per-locale page duplication, hydration, content request, locale persistence, or browser-language detection.

`src/pages/index.astro` explicitly refreshes to the mapped Russian home. Native `redirectToDefaultLocale` is disabled: in the installed Astro version combining the automatic redirect and an explicit root page causes a route-conflict warning. Phase 06 wraps the meta refresh and visible destination link in BaseLayout so the static root also carries noindex. It is not an HTTP 302 on a generic static host; deployment-specific HTTP redirects can be added later. The redirect works with JavaScript disabled.

## Route identity and availability

`src/i18n/routes.ts` owns stable page IDs and locale-specific slugs. Paths are mapped explicitly, so future translated slugs need no translation guessing. `localizedPath` delegates URL formatting to Astro's native `getRelativeLocaleUrl`. `validateRoutes` rejects duplicate IDs, duplicate paths per locale, unsupported locale keys, unsafe slugs, and a Russian redirect policy without a Russian target.

`resolveRoute` distinguishes an available translation, an explicitly configured `missing: 'redirect-ru'` target, and an unavailable route (`undefined`, meaning 404). `localizedPath` returns the Russian destination for a configured fallback. Without that policy, callers omit the link or serve 404. Arbitrary unknown page IDs are authoring errors; unknown URLs return 404. No slug is guessed for a nonexistent translation.

`availableTranslations` returns only real translations, excluding redirect targets. Both current pages are complete in both languages. Missing-translation behavior is exercised with unit fixtures; there is no fabricated missing business page in the public dataset. If a future route requires a direct redirect from an unpublished locale URL, explicitly configure that alias in Astro redirects at the known missing URL; do not add it to the available-translation map. Static hosts require their own configuration for HTTP redirect status codes.

## UI dictionaries

`src/i18n/dictionaries/ru.ts` defines semantic keys and the `Dictionary` contract. `kk.ts` uses `satisfies Dictionary`, requiring equivalent keys without constraining their values to Russian literals. Interface text includes navigation labels, generic actions, accessibility labels, and the fictional-review preview notice. Business names, descriptions, services, and marketing copy stay in content data.

`t(locale, key)` resolves a typed key. A missing or blank runtime dictionary value logs a warning containing locale/key and returns the Russian value. It never renders a raw key. This happens during build/dev rendering; there is no client translation library. `translate` exposes the same small fallback behavior for boundary tests. Use native `Intl` APIs if number/date/plural formatting becomes necessary.

Reusable components receive resolved labels through their existing props. The language switcher also receives resolved link models and its accessible label; it imports no business data, dictionaries, or route-resolution logic.

## Business-content policy

Required business translations must be present and nonblank for every published locale. Missing fields fail validation with record/field/locale context. They do not silently fall back to Russian. Locale-separated service/page entries use stable identity across translations, with uniqueness scoped to `(id, locale)`.

Optional business fields may be absent. This dataset has no configured Russian fallback for optional fields; for example, an address present only in Russian is omitted in Kazakh. Future optional fallback must be explicitly implemented and documented for that content type. See [content.md](./content.md) for the boundary and source representations.

## Language switching and metadata

`LanguageSwitcher.astro` fits Header's existing `language` slot. It uses native anchors, native-language labels, `lang`, `hreflang`, and `aria-current="true"` for the active language. It wraps on narrow screens and works with keyboard activation and JavaScript disabled. Only available translations appear, preserving the equivalent page rather than returning to Home. Missing translations are omitted; configured Russian fallback URLs remain available to navigation callers through `localizedPath`.

Phase 06 adds optional resolved `seo` to BaseLayout while preserving its older metadata props and safe noindex default. SEOHead consumes normalized page metadata and `availableTranslations`, producing localized canonicals from the validated deployment origin. Only eligible production equivalents receive reciprocal head hreflang, including self and a direct Russian `x-default` when eligible. Noindexed, missing, and redirected counterparts are excluded. Language switching continues to show real available pages independently of indexing policy. Static paths also enumerate available translations, preserving the route registry as the authority.

`metadata.indexable` now combines with explicit deployment policy; the fictional dataset keeps false in both locales. Head hreflang is therefore absent from shipped demo and authored production samples even though navigation language links remain present. The eligible isolated production fixture exercises actual reciprocal metadata. Open Graph, sitemap filtering, robots, JSON-LD, and origin configuration are documented in [seo.md](./seo.md). No parallel route map or Russian metadata fallback is introduced.

## Fonts and verification

The inherited system Arial/Times New Roman theme stacks remain unchanged. Phase 02 verified the installed Windows regular/bold font cmap tables for Russian and `Ә Ғ Қ Ң Ө Ұ Ү Һ І ә ғ қ ң ө ұ ү һ і`. Kazakh content is exercised in both browsers. System-font availability elsewhere remains platform-dependent; verify any future brand font independently.

Unit tests cover both localization representations, resolved contracts, missing required translations, optional fields, invalid locales, scoped duplicate identities, dictionary parity/fallback warnings, translated slugs, Russian redirect targets, and missing-page exclusion. Vitest uses a small double for Astro's build-configured virtual URL module and a metadata fixture for imported PNGs. Production Playwright tests exercise the actual Astro helper, generated metadata, optimized image references, and routing.

Chromium and Firefox cover root redirection, all four pages without JavaScript, correct language and metadata, equivalent-page switching with keyboard activation, localized navigation, visible content, 320/768/1440px layouts, 200% root text at 640px, no raw UI keys, and no fetch/XHR content traffic. Development previews compare the exact service block markup from both representations. See [content.md](./content.md) for final command results.

## Adding a locale or page

1. Add the locale to `locales`, update `parseLocale`, labels, and dictionary registration.
2. Add a dictionary satisfying `Dictionary`; fill all required business translations and locale-separated entries.
3. Map published slugs under the stable route ID. Add a corresponding explicit composition for a new page type and its content model where needed.
4. Keep only published translations in the map. Configure Russian fallback deliberately or let unknown URLs return 404.
5. Verify normalization, links, metadata, keyboard switching, reflow, and font glyph coverage; rerun the relevant checks.
